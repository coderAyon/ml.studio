## Scope and decision

Baseline: `3f24d0375170ad069b8567609f30c3a8469eebb4` on `main`, origin `coderAyon/ml.studio`. This phase inspects and verifies the existing product; it does **not** implement the proposed repairs. Application source, dependencies, architecture and executable are unchanged. Documentation and isolated synthetic audit evidence are the only additions.

ML Studio is a real, bounded tabular workbench, with useful processing and evaluation already implemented. Passing the current suite does not establish correctness for all supported data types or editing histories. Reproduced failures in cache identity, serialization and evidence validation should precede additional algorithms or interface expansion. Keep Python + Qt WebEngine/QWebChannel + local JavaScript + scikit-learn + SQLite. No broad rewrite is justified by this audit.

The selected initial improvements are **immutable revision/cache identity**, **lossless project/research data persistence**, and **shared held-out evidence validation**. Their bounded implementation plan is [here](superpowers/plans/2026-10-28-engineering-correctness.md). Other P0 repairs remain explicitly open; completing these three will not mean P0 is finished.

## Risks and test gaps, distinguished from reproduced failures

- Prediction intentionally tolerates unknown categories. A Boolean-trained field arriving as integers can be stringified to entirely unseen values and change predictions without an actionable drift review. Add observed dtype/domain/unseen-category diagnostics, preserving an explicit compatibility decision rather than banning every new category.
- External workflow files can change with the same size/mtime or while being read. Hash loaded content and verify before/after source consistency in a later bounded repair; file-stat equality is not a data fingerprint.
- Test names overstate some coverage: `tests/test_audit_fixes.py::test_model_roundtrip_and_untrusted_types` tests a safe roundtrip and missing file, not actual rejection of unknown types. `test_preprocessing.py` permits reported/detail count differences. Add semantic regression assertions before fixing each case.
- No CI workflow is tracked under `.github`. Local green results currently have no reproducible clean-environment CI gate.
- Worker completion/history publication has no execution-generation or cancellation contract. Global busy restrictions reduce concurrent mutation risk but do not substitute for cancellation-safe results and cleanup.
- SHA-256 inside an archive detects accidental changes, not authorship or publisher authenticity. Do not describe model integrity checks as a trusted signature.
