# Project and research snapshot formats

New snapshots use `typed-v4` through `project_data.pack_frame/unpack_frame`. Ordinary project JSON retains project schema 1; its embedded snapshot identifies its own encoding. New Research Packs use manifest schema 2 and put the same typed snapshot in `frame.json`. Research schema 1 keeps its historical table-JSON reader.

Typed-v4 columns are positional, named descriptors with an explicit row count. Primitive numeric values use base64 little-endian buffers and declared primitive dtypes. Nullable numeric/Boolean columns retain separate data and mask buffers. Datetimes retain integer epochs, s/ms/us/ns units and supported timezone names/offsets; categorical columns retain codes, unused domain values, domain dtype and ordering. Text retains `str` versus nullable `string` missing semantics and its declared supported storage. Primitive object cells use a fixed set of scalar tags, not arbitrary class reconstruction. There is no pickle/joblib input or executable object decoding.

The canonical SHA-256 covers encoding, dimensions, descriptors, values and persisted provenance. The reader also validates buffer lengths, primitive dtype whitelists, Boolean masks, category codes and descriptor shapes. An internally consistent checksum does not authorize an invalid descriptor. Checksums detect changes; they do not authenticate an archive's author.

Supported value families include NumPy booleans/integers/unsigned integers/float16/32/64, pandas nullable numeric/Boolean values, pandas text, datetime/timedelta units s/ms/us/ns, categoricals over supported domains, and explicitly supported primitive object scalars. Unknown dtypes, arbitrary object cells and unsupported timezone representations fail explicitly before replacing an existing project/export. Optional string storage must be available in the reopening environment; the core does not download it.

Only import provenance attributes `duplicate_headers`, `arff_relation` and `arff_schema` are retained, and they must contain finite, JSON-safe values. Arbitrary attributes are intentionally omitted. Row indexes normalize to a RangeIndex, matching the previous snapshot contract; original CSV row identity is not inferred from an arbitrary pandas index. Datetime frequency hints on a categorical domain are not persisted; exact domain values, units, timezone and ordering are retained. Very large integer persistence/export accuracy does not certify JavaScript chart/table rendering above its numeric safe-integer range.

Legacy snapshots with no encoding, `typed-v1`, `typed-v2` and `typed-v3` remain readable under their original checksum/overlay recipes. Already-lost values in an old lossy export cannot be recovered; use the original data if an older snapshot lost integer/timestamp precision. Unknown encoding and research schema versions return explicit errors instead of silently selecting a legacy reader.

Generated replay packages include the codec and required source modules. Acceptance checks run outside the checkout, remove inherited PYTHONPATH, and verify that imported ML Studio modules resolve inside the extracted package. CSV remains an inspection/export representation; replay reconstructs the checked typed snapshot and validates the exact recorded splits. No clean-machine installer claim follows from a successful replay in the existing scientific runtime.
